Part 0 — Foundations & Mental Models

Welcome to the lab. We begin with mental clarity before touching code.

0.1 The Vocabulary

Let’s define every term carefully as established in the course foundations.

🤖 1. Codex Plugin

What it is: An AI coding assistant in VS Code.

Does: Reads workspace, writes code, runs terminal commands.

NOT: Your backend, production runtime, or agent logic.

🧠 2. Agent

A system that has a goal and owns the decision loop. Without this loop (Plan → Act → Observe), you do not have an agent.

⚡ 3. Skill

Passive expertise and reusable instruction bundles. A skill is expertise; an agent is behavior. Skills do not loop or execute tools directly.

🔌 4. MCP Server

A standardized, passive bridge between models and systems. It waits for requests and does not make decisions.

0.4 Two Kinds of Agents

This distinction is subtle but critical:

  • Type A (Development Agent): Codex in VS Code. It builds the system.
  • Type B (Runtime Agent): The agent you write in your app (e.g., a task planner).

Key Insight: Codex builds runtime agents. Codex ≠ your runtime agent.

0.5 - 0.7 Concrete Example: Task Manager

Option 1: No Agent

User: "Add buy milk"
System writes to file. Done. No decisions. No loop.

Option 2: With Agent

Agent reads tasks, groups priority, estimates time, suggests schedule. Planning & Iteration exists.

Skills in this example: Scheduling heuristics and time estimation rules.
MCP in this example: Provides tools like `task.read_all` and `calendar.reserve_slot`.
