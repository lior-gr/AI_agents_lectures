P3 Tool schema concept

Understand the contract before writing behavior.

Definition

schema = interface contract, implementation = behavior

What this means here

  • Schema: names, descriptions, and argument shapes the model can call.
  • Implementation: the real Python functions that execute actions.
  • You can define schema first, even when implementation is still stubbed.
tools.py TOOL_SCHEMAS # contract execute_tool(...) # behavior (stub first, real later) agent.py uses contract and behavior in separate implementation steps

Schema explainer and usage examples

  • Schema lives in tools.py.
  • Schema declares tool names and argument shapes; it does not execute behavior.
  • Execution behavior will be stubbed first, then implemented later without changing the contract.
# tools.py (contract)
TOOL_SCHEMAS = [
  {
    "type": "function",
    "function": {
      "name": "delete_tasks",
      "description": "Delete one or more tasks by IDs.",
      "parameters": {
        "type": "object",
        "properties": {
          "task_ids": {"type": "array", "items": {"type": "integer"}}
        },
        "required": ["task_ids"]
      }
    }
  }
]

OpenAI API key concept and shell setup

  • OPENAI_API_KEY is a secret credential used by your runtime app to authenticate API calls.
  • API usage has real cost; set billing budgets/limits and usage alerts before running repeated tests.
  • Never hardcode it in source files, never commit it to git, and load it from environment variables at runtime.
How to create an OpenAI API key
  1. Sign in to platform.openai.com with your account.
  2. Open the dashboard, then go to the API keys page.
  3. Select your project (or create one), then click create new secret key.
  4. Give the key a clear name, create it, and copy it immediately (it is shown once).
  5. Store the key in a secure password manager, then set it in your shell as OPENAI_API_KEY.
  6. Set usage limits and alerts in billing settings to control spend.
Shell Command
PowerShell $env:OPENAI_API_KEY = "your_key_here"
Unix bash export OPENAI_API_KEY="your_key_here"
Unix tcsh setenv OPENAI_API_KEY "your_key_here"

P8 Checkpoint and next lesson

Confirm understanding before moving to MCP decoupling.

  1. Where does schema live in this lesson?
    In tools.py, as TOOL_SCHEMAS.
  2. Why can schema exist before implementation?
    Because schema defines the interface contract; behavior can be added later.
  3. In which step should real OpenAI call first appear?
    Agent Step 4, after loop/logger/tools are already in place.
  4. Who owns loop control in this architecture?
    agent.py owns loop control (steps, stop conditions, and orchestration).
  5. Does storage know that an agent exists?
    No. storage.py remains model-agnostic and unaware of agent/runtime orchestration.
