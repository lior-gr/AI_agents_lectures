Appendix B - Concrete deterministic skill router

This appendix gives a practical, debug-friendly implementation of load_skills(goal). The focus is clarity, predictability, and easy testing.

B Concept before coding

Deterministic rules are easier to debug than free-form model choices.

Skill folder baseline

  • skills/always_on.md
  • skills/task_planning.md
  • skills/status_reporting.md
  • skills/output_format.md

Simple example

Goal: "Summarize tasks in JSON"
Expected selected skills: always_on + status_reporting + output_format.

B Add deterministic load_skills implementation

This changes prompt construction only.

Prompt to paste into Codex 
In agent.py, implement a concrete deterministic load_skills(goal: str) router.
Requirements:
- Use skill files: always_on.md, task_planning.md, status_reporting.md, output_format.md
- Apply ordering:
  1) always_on
  2) domain skill(s)
  3) output_format
- Use keyword triggers:
  task_planning: plan/organize/schedule/today/this week
  status_reporting: status/report/summary/summarize
  output_format: table/markdown/csv/json/pretty
- Concatenate selected skill text with separator "\\n\\n---\\n\\n"
- Do not change agent loop
- Do not change tool execution
Student task after generation
  • Test 4-5 goals and verify expected skill combinations.
  • Temporarily print selected skills for manual verification.
  • Remove debug prints after validation.

B Watch for common mistakes

Small mistakes here create large confusion later.

Avoid these

  • Letting model decide skill set in this deterministic appendix.
  • Putting tool call instructions directly inside skill files.
  • Modifying MCP server for skill logic.
  • Changing loop flow while adding skills.

Checkpoint

  1. Is load_skills deterministic here?
    Yes. It is keyword-driven with fixed ordering.
  2. Should MCP know about skills?
    No. Skills are prompt logic, MCP is execution boundary.
