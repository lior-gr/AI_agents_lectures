What this repository actually builds

The clips reflect the implemented end-to-end app under task_manager/.

  • Deterministic CLI task manager with JSON persistence.
  • Bounded agent loop with tool-calling and structured progress events.
  • MCP subprocess boundary for tool execution (client/server over JSON stdio).
  • Skills integration (deterministic and bounded routing) without changing loop control.
  • PySide6 UI that reuses shared backend entry points and shows live progress in table/tree views.

High-speed learning process (VS Code + Codex)

This sequence matches the tutorial itself, without introducing any extra tools or UI.

  1. Read the lesson background and boundaries.
  2. Implement the concept in VS Code with Codex.
  3. Run and test the change.
  4. Review with checklist and checkpoint.
  5. Advance to the next lesson page.

No invented tooling: this sequence stays in VS Code + Codex + lesson pages.

Learning loop (repeat this for every lesson)

  • Read the concept section and the simple example first.
  • Copy the prompt block and send it to Codex.
  • Do the student review checklist after code is generated.
  • Answer the checkpoint questions, then reveal the answers.

Why this structure works

It keeps coding and learning synchronized. You do not just generate code; you also understand why each architecture decision exists.
