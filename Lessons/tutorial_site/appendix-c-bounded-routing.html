Appendix C - Bounded model-assisted skill routing

This is the next step after deterministic keyword routing. You keep model flexibility for intent classification while enforcing strict validation.

C Concept before coding

Model helps choose from a fixed enum, validator enforces the contract.

goal text -> router model call -> JSON output -> deterministic validator -> selected skills -> prompt construction -> unchanged agent loop

Safety contract

  • Allowed skills are fixed in code.
  • Router output must be strict JSON with exact keys.
  • Invalid output triggers retry.
  • No keyword fallback in this mode.

Simple example

Router returns unknown skill name -> validator rejects -> retry until max attempts -> fail state.

C Create dedicated router module

Keep it pure Python and testable.

Prompt to paste into Codex 
Create a new file skill_router.py.
Implement a bounded model-assisted router:
route_skills_with_model(goal: str, call_model_fn, max_attempts: int) -> (ok, skills, reason)
The router must:
- Build a routing prompt that lists allowed skill enum and descriptions
- Demand JSON only
- Validate JSON deterministically
- Retry until success or fail state after max_attempts
- No keyword fallback
Keep code standard library only (json, typing).
Add comments explaining why this is safe and debuggable.
Use ASCII only in strings.
Student task after generation
  • Verify unknown skills, duplicate skills, wrong keys, and non-JSON are rejected.
  • Verify exported symbols include ALLOWED_SKILLS and router function.
  • Verify code is independent and unit-test friendly.

C Wire cheap router call path into agent

Routing should be low-cost and not affect loop mechanics.

Prompt to paste into Codex 
In agent.py, create helper call_router_model(messages) -> str:
- low temperature (0 or close)
- small max_output_tokens
- return raw text only
Then wire it into route_skills_with_model.

Prompt construction behavior:
1) Always load skills/always_on.md
2) Route optional skills via route_skills_with_model(..., max_attempts=3)
3) If routing fails, use always_on only
4) Concatenate skill text with "\\n\\n---\\n\\n"

Requirements:
- Do not change agent loop structure
- Do not change tool execution logic
- Add comments: routing affects reasoning only
Student task after generation
  • Confirm main model call path is unchanged.
  • Confirm router stage appears in progress/debug log.
  • Confirm fail-state behavior uses always_on only.

Checkpoint

  1. Who controls allowed skill names?
    The deterministic enum and validator in router code.
  2. What happens after max failed routing attempts?
    Fail state: continue with always_on only.
  3. Does this change control flow?
    No. It changes reasoning input, not loop mechanics.
