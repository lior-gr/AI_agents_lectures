A.2 Deterministic router contract

Define stable behavior before coding.

Why multiple skills?

Real agents need modular instruction layers: domain logic, output format rules, and always-on safety policy. Separation keeps prompt behavior explainable and testable.

Contract

  1. Input: goal text and available skill files.
  2. Output: one ordered concatenated skill text block.
  3. Always include always_on first.
  4. Add domain skills only when explicit triggers match.
  5. Add output formatting skill last.
Prompt composition (deterministic): base system policy + always_on + optional domain skills + optional output_format + user goal Runtime mechanics unchanged: agent loop unchanged MCP tool execution unchanged

A.3 Layout and trigger sets

Use explicit files and explicit keywords.

Recommended skills layout

skills/
  always_on.md
  task_planning.md
  status_reporting.md
  output_format.md

Keyword trigger sets

  • task_planning: plan, organize, schedule, today, this week
  • status_reporting: status, report, summary, summarize
  • output_format: table, markdown, csv, json, pretty

A.4 Reference code: load_skills(goal)

This changes prompt construction only.

Reference implementation 
import os
from typing import List


def _read_text_file(path: str) -> str:
    """Read a UTF-8 text file. Return empty string if missing."""
    try:
        with open(path, "r", encoding="utf-8") as f:
            return f.read().strip()
    except FileNotFoundError:
        return ""
    except OSError:
        return ""


def _contains_any(text: str, keywords: List[str]) -> bool:
    t = text.lower()
    return any(k in t for k in keywords)


def load_skills(goal: str, skills_dir: str = "skills") -> str:
    """Deterministically select skills based on goal text."""

    selected_paths: List[str] = []

    # 1) Always-on policy skill
    selected_paths.append(os.path.join(skills_dir, "always_on.md"))

    # 2) Domain skills
    if _contains_any(goal, ["plan", "organize", "schedule", "today", "this week"]):
        selected_paths.append(os.path.join(skills_dir, "task_planning.md"))

    if _contains_any(goal, ["status", "report", "summary", "summarize"]):
        selected_paths.append(os.path.join(skills_dir, "status_reporting.md"))

    # 3) Output format skill
    if _contains_any(goal, ["table", "markdown", "csv", "json", "pretty"]):
        selected_paths.append(os.path.join(skills_dir, "output_format.md"))

    blocks: List[str] = []
    for p in selected_paths:
        txt = _read_text_file(p)
        if txt:
            blocks.append(txt)

    return "\n\n---\n\n".join(blocks)

A.5 Integration steps and student tasks

Connect router output without changing execution paths.

Prompt to paste into Codex 
In agent.py, integrate load_skills(goal) into prompt construction.
Requirements:
- Call skills_text = load_skills(goal)
- Inject skills_text after base system policy and before user goal
- Do not change agent loop structure
- Do not change tool execution path

Explanation channel contract:
1) In-file comments:
   - non-obvious ordering logic
   - missing-file behavior and edge-case intent
2) Codex chat explanation:
   - what changed and why
   - test steps and expected outcomes
3) Both:
   - critical logic that preserves runtime behavior while changing reasoning input
Student verification
  • Confirm skill text is injected in the expected location.
  • Confirm agent loop and MCP tool calls are unchanged.
  • Confirm optional skills appear only when triggers match.

Verify selected skills for each goal.

"Give me a status report of my tasks" always_on + status_reporting
"Plan my tasks for today in a markdown table" always_on + task_planning + output_format
"Summarize my tasks in JSON" always_on + status_reporting + output_format
"List tasks" always_on only (typically no domain skill)

A.7 Common mistakes

Avoid these regressions when implementing deterministic routing.

  1. Letting the model choose skills in a deterministic router.
  2. Putting tool execution instructions in skill files.
  3. Mixing skill routing logic into MCP server code.
  4. Changing the agent loop while adding skill loading.

A.8 Checkpoint

Use active recall before moving to bounded routing in Appendix B.

Checkpoint questions

  1. Are skills executed or injected?
    Injected into prompt context, not executed as tools.
  2. Is this router deterministic or model-driven?
    Deterministic: explicit keyword rules and fixed ordering.
  3. Does MCP need to know which skills were loaded?
    No. MCP handles tools, not prompt composition choices.
  4. If output_format is removed, can planning still work?
    Yes. Planning logic still runs; output style control is reduced.
