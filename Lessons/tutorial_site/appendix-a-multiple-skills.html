Appendix A - Multiple skills and skill selection

This appendix helps you scale from one skill to several skills without losing clarity. You will keep skill usage structured and deterministic.

A Concept before coding

Use multiple skills like modules with clear responsibilities.

Common skill groups

  • Always-on skill: global constraints and policy.
  • Domain skill: planning or reporting logic.
  • Output skill: formatting preferences.
Recommended order: 1) always_on 2) domain skill 3) output skill

Simple example

Goal: "Plan my tasks in markdown table."
Useful stack: always_on + task_planning + output_format.

A Create multiple skill files

Keep each skill focused and execution-free.

Prompt to paste into Codex 
Create these files under skills/:
- always_on.md
- task_planning.md
- status_reporting.md
- output_format.md
Each file should clearly state:
- When it applies
- What it changes about reasoning
- What it must never do (no execution)
Use concise bullet rules.
Add a short comment block at the top: "This is a skill, not a tool."
Student task after generation
  • Check none of the skills contain tool execution details.
  • Check naming is consistent and easy to map.
  • Check each skill has clear apply/do-not-do sections.

A Add deterministic skill loading

Predictable routing first, model routing later.

Prompt to paste into Codex 
In agent.py, implement a function load_skills(goal: str) -> str that:
- Always loads skills/always_on.md
- Conditionally loads other skills using deterministic keyword rules
- Returns a single concatenated string to inject into the system prompt
Requirements:
- Do not change the agent loop
- Do not change tool execution
- Add comments explaining ordering and why routing is deterministic
Student task after generation
  • Test goals for planning, reporting, and formatting.
  • Verify selected skills appear in expected order.
  • Confirm MCP/tool execution path remains unchanged.

Checkpoint

  1. Are skills executed or injected?
    Injected into prompt context; they are not executors.
  2. Is this router deterministic or model-driven?
    Deterministic (keyword rules and fixed order).
