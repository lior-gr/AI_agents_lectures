Lesson 3 - Decouple execution with a minimal MCP boundary

We move tool execution behind a subprocess boundary, while keeping the same agent loop. This is where architecture separation becomes real.

L3 Concept before coding

The agent should not care where tools run.

Before: agent.py -> tools.py -> storage.py After: agent.py -> mcp_client.py -> mcp_server.py -> storage.py

What must stay unchanged

  • Agent loop structure.
  • Step counting and stop conditions.
  • Token handling path.

Simple example

Agent asks for list_tasks. It should not matter if that call is local or via subprocess.

L3 Create MCP server

Keep it synchronous and deterministic.

Prompt to paste into Codex 
Create mcp_server.py.
Requirements:
- Runs as a standalone Python process
- Reads JSON messages from stdin
- Writes JSON responses to stdout
- Supports:
  - add_task
  - list_tasks
  - complete_task
- Calls storage.py internally
- Includes detailed comments explaining:
  - Message format
  - Tool dispatch
  - Why this is decoupled from the agent
Keep it synchronous and simple.
Student task after generation
  • Validate request/response JSON format exactly.
  • Confirm no OpenAI calls exist in server code.
  • Confirm server handles unknown tool requests clearly.

L3 Create MCP client and rewire agent

Execution plumbing changes only.

Prompt to paste into Codex 
Create mcp_client.py.
Requirements:
- Starts mcp_server.py as subprocess
- Sends JSON requests
- Receives JSON responses
- Handles errors gracefully
Explains:
- Why subprocess boundary matters
- How this simulates real MCP architecture

Modify agent.py so tool calls go through mcp_client.py instead of tools.py.
Do not modify the agent loop structure.
Only replace the execution layer.
Add comments explaining why the agent remains unchanged.
Student task after generation
  • Confirm loop logic, stop conditions, token handling, and step counter are untouched.
  • Run one goal and inspect logs to confirm MCP path is active.
  • If loop logic changed, refactor and try again.

Checkpoint

  1. Does MCP server decide what action comes next?
    No. The agent decides; MCP executes.
  2. Should the agent loop change in this lesson?
    No. Only execution plumbing should change.
