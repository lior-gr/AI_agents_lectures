These outcomes define done for the UI boundary stage.

P2 Concept before coding

UI collects input and renders output. Nothing more.

GUI (ui.py) -> main.py shared backend -> agent -> MCP -> storage

UI must not do these

  • No direct OpenAI calls.
  • No tool execution logic.
  • No direct JSON writes.

Simple example

A submit click should call a shared backend function, not re-implement the agent loop inside UI code.

P3 Create a minimal UI file (Qt6)

Use a professional UI framework while keeping boundaries clean.

Qt6 background (short)

  • Qt6 is a mature cross-platform desktop UI framework.
  • PySide6 is the official Python binding for Qt6.
  • It uses an event-driven model (signals/slots), which fits app-style interfaces well.
  • It is heavier than Tkinter, but scales better for richer UIs.

P5 Add progress sidebar with selectable view modes

Primary reason: make agent execution flow visible so debugging is fast and reliable.

Why this section exists

This section exists to help you debug the agent execution flow step by step. The sidebar surfaces runtime progress events and lets you inspect them in table and tree views, without changing backend ownership.

Prompt to paste into Codex 
Extend the PySide6 UI to include an "Agent Progress" sidebar panel.

Requirements:
- Keep backend interface unchanged (main.py, agent loop, MCP, storage responsibilities stay the same).
- The sidebar must support selectable view modes:
  1) Table view
  2) Tree view
- Add a clear mode selector (tabs, segmented buttons, or combo box).

Table view requirements:
- Render one row per progress event.
- Include columns: Time, Type, Name, Details.
- Apply color classification by event type (for example: step_start, tool_called, tool_result, skill_route, skill_used, validation, stop, error).
- Keep text readable and aligned.

Tree view requirements:
- Show hierarchical structure (for example: run -> step -> events).
- Support expand/collapse per node.
- Add Expand all and Collapse all controls.

Behavior requirements:
- Live updates while the agent is running.
- Switching view mode must not lose data.
- No OpenAI logic in UI.
- No tool execution logic in UI.
- No direct storage writes in UI.

Add comments explaining separation of concerns and why this is UI instrumentation only.
Student task after generation
  • Run python main.py --gui and submit a goal that triggers multiple events.
  • Open the Agent Progress sidebar and confirm events appear live while the run is in progress.
  • Switch to Table view and confirm rows are color-classified by event type.
  • Switch to Tree view and confirm nodes can be expanded and collapsed.
  • Use Expand all / Collapse all and confirm both controls work correctly.
  • Switch between Table and Tree several times and confirm no events disappear.

Expected output after this stage

  • GUI includes a right-side Agent Progress panel.
  • The same event stream is viewable as Table and Tree.
  • Color classification improves scan speed in table mode.
  • Tree mode supports collapse/expand for fast structural understanding.

P6 What must remain true

If these boundaries break, architecture leaked.

  • agent.py remains the control loop owner.
  • mcp_server.py and mcp_client.py remain execution boundary components.
  • storage.py remains the persistence owner.
  • skills/ remains reasoning-only content.
  • UI must not introduce backend responsibility shifts.

P7 Test scenario

Validate that GUI and CLI hit the same backend behavior.

Behavior checks
  1. Run CLI: python main.py --goal "Add buy milk".
  2. Run GUI: python main.py --gui.
  3. Submit the same goal in GUI and compare result behavior with CLI.
  4. Confirm progress sidebar updates while the goal is running.

P8 Why this matters

This is architecture discipline, not cosmetic UI work.

  • UI should improve usability and observability, not own runtime logic.
  • Progress instrumentation reduces debugging time and clarifies failures.
  • Stable boundaries let you replace UI technology without rewriting core behavior.

We exclude deeper product-grade concerns here to keep the lesson focused on boundary correctness.

P10 What this teaches

Core learning outcomes from this lesson.

  • UI is a boundary layer.
  • The agent is a control system.
  • MCP is an execution boundary.
  • Skills shape reasoning, not execution.
  • Storage owns persisted state.

P11 Checkpoint and next

Quick reflection before moving to appendices.

Checkpoint

  1. Should GUI know OpenAI details?
    No. GUI should stay an interaction layer only.
  2. Can you replace the UI without changing agent logic?
    Yes, if backend boundaries are clean.
  3. Why is the progress sidebar important?
    It makes execution flow observable, so debugging tool calls and stop conditions is much faster.
