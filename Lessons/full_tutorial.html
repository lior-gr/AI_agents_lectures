P0 Part 0 - Foundations and Mental Models

Core vocabulary and interaction boundaries: Codex, Agent, Skill, MCP server, and tools.

Vocabulary summary
  • Codex is a development assistant, not your production runtime.
  • An agent owns a goal-driven loop: plan, act, observe, decide, repeat or stop.
  • A skill is passive reasoning guidance, not an executor.
  • An MCP server is a passive tool provider behind a boundary.
Human -> Codex (development) -> Project files -> Runtime app Human -> Runtime agent -> Skills (reasoning) + MCP (execution boundary) -> Tools -> System
Allowed Not allowed
Agent calls tools via boundary MCP server plans tasks
Skill shapes reasoning Skill runs subprocesses
Codex edits source code Codex used as production backend
Checkpoint (click to reveal answers)
  1. Does a skill ever run a subprocess?
    No. A skill is prompt-space guidance only.
  2. Does an MCP server decide when to call tools?
    No. The agent decides; MCP executes requests.
  3. Who owns the loop in an agent system?
    The runtime agent logic owns the loop.

Merged reference code

Appendix B was merged into this appendix on February 16, 2026. Use this deterministic router implementation as the baseline.

Ordering rule
  • Always inject always_on first.
  • Inject domain skills second.
  • Inject output format skill last.
def load_skills(goal: str, skills_dir: str = "skills") -> str:
    selected = [f"{skills_dir}/always_on.md"]
    if has_any(goal, ["plan", "organize", "schedule", "today", "this week"]):
        selected.append(f"{skills_dir}/task_planning.md")
    if has_any(goal, ["status", "report", "summary", "summarize"]):
        selected.append(f"{skills_dir}/status_reporting.md")
    if has_any(goal, ["table", "markdown", "csv", "json", "pretty"]):
        selected.append(f"{skills_dir}/output_format.md")
    return "\\n\\n---\\n\\n".join(read_non_empty(selected))

This appendix is deterministic by design. Easy to test and reason about, but weaker for synonyms.

B Appendix B - Bounded model-assisted skill routing

Replace keyword routing with a bounded model classifier that outputs strict JSON and is validated deterministically.

Contract summary
  • Allowed enum only: task_planning, status_reporting, output_format.
  • Return JSON only with exact keys: skills, confidence, notes.
  • Reject unknown skills, duplicates, wrong keys, and non-JSON responses.
  • Retry up to max_attempts; no keyword fallback.
